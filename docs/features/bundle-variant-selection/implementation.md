Los bundles nuevos permiten seleccionar una variante específica por componente. Un bundle configurado con el suplemento de 300 g no califica con el de 150 g, aunque ambos tengan el mismo nombre de producto. La variante elegida se muestra mediante atributos y SKU en configuración, sugerencias y carrito.

El cambio se preparó en `codex/bundle-variant-selection-20261026` desde `main` (`8a4e81b8e8a071f79c8c0b03f9299622cb6a8246`). No requiere modificar servicios ni base de datos.

- Los componentes nuevos guardan `productId`, `variantId`, atributos, SKU y precio de variante con `schemaVersion: 2`. Se mantiene el límite actual de 2–10 productos distintos.
- El motor usa `variantId` para elegibilidad, descuento, sugerencias y precios por componente. Revalida la configuración al aplicar y retira una aplicación cuyas líneas ya no corresponden a sus componentes.
- El autocompletado consulta la variante actual y busca su SKU actual dentro del almacén o catálogo de tienda seleccionado. Compara el ID exacto; una variante ausente o desactivada no se sustituye por otra. Ventas conserva su política de venta bajo pedido y cotizaciones exige stock.
- Se preservan los campos de seguimiento y selección de unidades de las líneas existentes. Los botones de sugerencias usan `type="button"` para evitar enviar una cotización al agregar o aplicar un bundle.
- Los bundles antiguos mantienen su alcance por producto. Editar nombre, precio o canales no los convierte. Elegir una variante o cambiar componentes exige completar todas las variantes antes de convertirlos.
- Los bundles exactos se almacenan en `powip.packs.variants.v1.<companyId>`. Bundles antiguos y regalos conservan `powip.packs.local.<companyId>`. Esto impide que clientes anteriores interpreten nuevos bundles restringidos como promociones para cualquier variante. Siguen siendo configuraciones locales del navegador.
